Recursion　遞迴

生活應用

你是班長，晚上接到老師的電話：「由於電腦教室設備臨時故障，維修需要時間，明天資訊課和後天的歷史課對調，請通知同學帶對課本。」怎麼做？

複習

我們前面學了迴圈，最直覺的做法是照座號打 30 通電話。可是你不想打 30 通，所以你決定：

打給座號 1 號的同學，請他往下通知下一個號碼的人。

1 號打給 2 號、2 號打給 3 號……每個人做的事一模一樣：接到電話，再打給下一個；30 號後面沒有人，就停。把工作做自己的那一份、剩下的交給下一個，這種寫法叫遞迴。

核心觀念

遞迴（recursion）是函式呼叫自己。班長的辦法寫成函式 notify(k, n)：通知 k 號同學，再呼叫 notify(k + 1, n)，請他去通知剩下的人。每一號做的事一模一樣，所以一個函式就寫完了，不用寫 30 次。

一個遞迴有兩個部分。終止條件（base case）：問題已經小到可以直接回答，不用再呼叫自己，像 k 是最後一號 n，就不再往下打。遞迴的那一步（recursive case）：把問題縮小一點，再呼叫自己，像從「通知 k 號以後的人」變成「通知 k + 1 號以後的人」。少了終止條件，或每次呼叫沒有往終止條件靠近，就停不下來。

每呼叫一次就是新的一層，參數各自一份：notify(1, 3) 呼叫 notify(2, 3) 的時候，自己那一層的 k 還是 1，在旁邊等它回來。最後一層最先回傳，交回上一層，上一層把那一行做完再往回交，一路回到第一層。

後呼叫的先回來，就是後進先出，所以電腦用一個堆疊記每一層，叫呼叫堆疊（call stack）。資料結構的堆疊頁也會再講到它。 → 堆疊

費氏數列 fib(n) = fib(n − 1) + fib(n − 2) 照定義寫成遞迴很漂亮，可是 fib(n − 1) 裡面又會再算一次 fib(n − 2)，同樣的東西被重複算了很多次。下面「跑幾步」數給你看。

什麼時候會用到

  • 排隊時想知道自己是第幾個：問前面的人「你是第幾個？」，他再往前問，問到第一個人說「我是第 1 個」，答案一路傳回來，每個人加 1 就知道了。
  • 算一個資料夾有多大：裡面的檔案加起來，再加上每個子資料夾的大小，子資料夾也用同一個方法算，算到沒有子資料夾為止。
  • 家族樹、公司的組織圖、網站的選單：一個節點底下接著幾棵小一點的樹，走訪整棵樹就是「看自己，再對每棵小樹做同一件事」。 → 樹
  • 電腦內部：合併排序、快速排序把陣列切成兩半各自排好；APCS 實作題常見的走迷宮、DFS，都是寫成遞迴。 → 排序

常見誤解

誤解：每一層遞迴共用同一個 k

正解：每呼叫一次，參數就重新開一份：notify(1, 3) 那層的 k 是 1，它呼叫的 notify(2, 3) 那層 k 是 2，改其中一層不會動到別層。追蹤器的呼叫堆疊上，一層一個 k。

誤解：沒寫終止條件，遞迴也會自己停

正解：它會一直呼叫自己，直到呼叫堆疊塞滿：C、C++ 通常整個當掉（stack overflow），Java 丟 StackOverflowError，Python 預設大約 1000 層就報 RecursionError。

誤解：有終止條件就一定會停

正解：每次呼叫都要讓問題變小，往終止條件靠近。把 notify(k + 1, n) 寫成 notify(k, n)，k 永遠到不了 n；階乘的終止條件是 n == 1，呼叫 fact(0) 會一路減成負數、碰不到 1，一樣停不下來。

誤解：return 會直接回到主程式

正解：return 只回到呼叫它的上一層。notify(3, 3) 回傳 1 給 notify(2, 3)，它加 1 變 2 再交給 notify(1, 3)，再加 1 變 3，才回到主程式（追蹤器挑 n = 3 看看）。

誤解：遞迴一定比迴圈好

正解：遞迴常常寫得比較短、比較貼近定義，可是每一層都要記在呼叫堆疊上。費氏數列照定義寫，fib(30) 要呼叫 2692537 次；用迴圈從 fib(0)、fib(1) 往後算，30 圈就到了。

實作

C

#include <stdio.h>

int fact(int n) {
    if (n == 1) {                       // 終止條件：1! 就是 1
        return 1;
    }
    return n * fact(n - 1);             // 縮小一點：n! = n × (n - 1)!
}

int fib(int n) {
    if (n <= 1) {                       // 終止條件：fib(0) = 0、fib(1) = 1
        return n;
    }
    return fib(n - 1) + fib(n - 2);     // 照定義寫：前兩項相加
}

int gcd(int a, int b) {
    if (b == 0) {                       // 終止條件：除得盡了，a 就是最大公因數
        return a;
    }
    return gcd(b, a % b);               // 輾轉相除：換成 b 和 a 除以 b 的餘數
}

int main(void) {
    printf("%d %d %d\n", fact(5), fib(10), gcd(48, 18));
    return 0;
}

跑幾步

追蹤器的 notify(1, n)：每一號呼叫一次（n = 3 時呼叫 3 次）n 次，O(n)
實作的 fact(n)：n、n − 1、…、1 各一層n 次，O(n)
照定義寫的 fib(n)：每一層又呼叫兩次（fib(5) 呼叫 15 次、fib(10) 呼叫 177 次）n 每加 1，次數大約變 1.6 倍，O(2ⁿ)

遞迴跑幾步，數的是函式一共被呼叫幾次、每次呼叫做多少事。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

程式測試與除錯2. 想算 5!（5 × 4 × 3 × 2 × 1 = 120），結果印出 0。要怎麼改？

C

int fact(int n) {
    if (n == 1) {
        return 0;
    }
    return n * fact(n - 1);
}

printf("%d\n", fact(5));
  1. 把 n == 1 改成 n == 0
  2. 把 fact(n - 1) 改成 fact(n)
  3. 把 n * fact(n - 1) 改成 n + fact(n - 1)
  4. 把 return 0 改成 return 1

程式效能分析3. 用 calls 數 fib 被呼叫了幾次。下面這段程式跑完 fib(5)，印出的 calls 是多少？

C

int calls = 0;

int fib(int n) {
    calls += 1;
    if (n <= 1) {
        return n;
    }
    return fib(n - 1) + fib(n - 2);
}

fib(5);
printf("%d\n", calls);
  1. 15
  2. 5
  3. 6
  4. 32

總結

notify(k) 做兩件事：通知 k 號，再 notify(k + 1)；k 是最後一號時不再往下打。下次碰到一件事可以拆成「做自己這份，剩下的交給下一個」，你就知道：這就是遞迴，記得寫停下來的條件。

課外補充

記住算過的答案（記憶化，memoization）：開一個陣列 memo，算出 fib(k) 就記在 memo[k]，下次要用先查表，查得到就直接拿。每個 fib(k) 只真的算一次，fib(30) 從呼叫兩百多萬次變成 30 次左右，O(n)。

Python 預設最多疊大約 1000 層，超過就報 RecursionError。可以用 import sys 再寫 sys.setrecursionlimit(10000) 調高上限，可是層數太深，底下的程式還是會把堆疊用完、整個當掉；遞迴要疊很深的時候，改寫成迴圈比較穩。
