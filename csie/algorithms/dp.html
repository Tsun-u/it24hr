Dynamic Programming　動態規劃

生活應用

一段 14 階的樓梯，每一步可以跨 1 階或 2 階。如果每天換一種走法，你可以連續走多久都不重複？

複習

我們學過遞迴。要走到第 14 階，最後一步不是從第 13 階跨 1 階上來，就是從第 12 階跨 2 階上來，所以走法數＝走到第 13 階的走法＋走到第 12 階的走法。寫成遞迴，14 階一下就算完；可是換成幾百階的登山步道，同一支程式算到天荒地老都算不完。 → 遞迴

翻開它的呼叫：算 14 階的時候，走到第 12 階的走法被算了 2 次、第 11 階 3 次、第 10 階 5 次……同一個答案一算再算。

算過的答案記下來，下次直接拿來用，不要再算一次。

核心觀念

動態規劃（dynamic programming，簡稱 DP）是把大問題拆成比較小的同樣問題，每個小問題的答案記在一張表上，從小的填到大的。走樓梯的表是 ways：ways[n] 是走到第 n 階的走法數，ways[n] = ways[n − 1] + ways[n − 2]。

能這樣做要有兩個條件。第一，大問題的答案可以由小問題的答案組起來：走到第 n 階，只能從第 n − 1 階或第 n − 2 階上來，這條式子叫遞迴關係（求最好的方案時，教科書叫它最佳子結構，optimal substructure）。第二，同樣的小問題一再出現（重疊子問題，overlapping subproblems）：上面的圖解裡，算 5 階要算兩次 3 階、三次 2 階。只有第一條、沒有重疊，記下答案也沒有東西可以省。

表的最前面幾格要直接寫答案，叫初始值：走到第 1 階只有 1 種走法、第 2 階有 2 種（1＋1、2）。其他格子都從這兩格長出來，所以初始值錯一格，後面全錯。

兩種填法。由上而下（top-down）：照原本的遞迴寫，多一個 memo 陣列，算出答案就記下來，下次先查表，這叫記憶化（memoization），遞迴頁的課外補充講過。由下而上（bottom-up）：不用遞迴，用迴圈從初始值往後一格一格填，這叫填表（tabulation），下面的追蹤器就是這種。兩種都是動態規劃，每一格都只算一次。 → 遞迴

名字裡的 programming 不是寫程式，是規劃、排出最好的方案，跟線性規劃（linear programming）的 programming 同一個意思。這個名字是美國數學家 Richard Bellman 在 1950 年代取的，他研究的是一步一步做決定的問題。

什麼時候會用到

  • 出國打包：行李箱限重 20 公斤，每樣東西有重量、也有多想帶，要帶哪幾樣最划算？一樣一樣考慮「帶或不帶」，把每種限重下的最好答案記在表上，這叫背包問題（knapsack）。 → 背包問題
  • 打錯字時，軟體建議你可能想打的字：從字典裡找出跟你打的字差最少的那個。兩個字串差幾個字母（改一個、加一個、刪一個各算一步），叫編輯距離（edit distance），用一張表從短的前綴算到長的。
  • 比對兩份文件哪裡不一樣，像程式碼改版前後的 diff：找出兩邊都有、順序也一樣的最長那一串（最長共同子序列，LCS），剩下的就是改過的地方。
  • APCS 實作題的中高級常考：背包、最長共同子序列、最長遞增子序列，還有在格子地圖上從左上走到右下有幾種走法。

常見誤解

誤解：動態規劃一定要用遞迴寫

正解：由上而下（遞迴加記憶）和由下而上（迴圈填表）都是動態規劃。考試手寫常用填表：不用想遞迴怎麼停，也不會有遞迴疊太深、把呼叫堆疊用完的問題。

誤解：能寫成遞迴的問題，記下答案都會變快

正解：要有重疊的小問題才有得省。合併排序把陣列切成兩半各自排，兩半沒有重疊，每個小問題本來就只算一次，記下來也省不到。

誤解：表格從哪裡開始填都可以

正解：每一格要用到的格子要先填好。ways[i] 用到 ways[i − 1] 和 ways[i − 2]，所以 i 要從小填到大；倒過來填，會拿到還沒算、還是 0 的格子（試試看第二題）。

誤解：初始值寫錯一點沒關係，後面會修正回來

正解：表的每一格都從初始值長出來。把 ways[2] 寫成 1，ways[14] 就從 610 變成 377，整張表都跟著錯。

誤解：走法數再大，int 都裝得下

正解：走法數長得很快：ways[45] 是 1836311903，ways[46] 就超過 int 的上限 2147483647。C、C++、Java 的 int 會溢位變成負數，Python 的整數沒有上限；要算更多階，C／C++ 改用 long long、Java 改用 long。

實作

C

#include <stdio.h>

int memo[50];                           // memo[n] 是 0 代表還沒算過

int climb_memo(int n) {                 // 由上而下：照遞迴寫，算過的記下來
    if (n <= 2) {                       // 初始值：1 階 1 種、2 階 2 種
        return n;
    }
    if (memo[n] == 0) {
        memo[n] = climb_memo(n - 1) + climb_memo(n - 2);
    }
    return memo[n];
}

int climb_table(int n) {                // 由下而上：從初始值往後一格一格填
    if (n <= 2) {
        return n;
    }
    int ways[n + 1];
    ways[1] = 1;
    ways[2] = 2;
    for (int i = 3; i <= n; i++) {
        ways[i] = ways[i - 1] + ways[i - 2];
    }
    return ways[n];
}

int main(void) {
    printf("%d %d\n", climb_table(14), climb_memo(40));
    return 0;
}

跑幾步

照遞迴直接算 ways(n)：同樣的小問題一算再算（ways(14) 呼叫 753 次、ways(40) 呼叫兩億多次）n 每加 1，次數大約變 1.6 倍，O(2ⁿ)
由上而下加記憶：每個 ways(k) 只真的算一次呼叫大約 2n 次，O(n)
由下而上填表：迴圈從 3 跑到 n，每一格做一次加法n − 2 圈，O(n)
表格佔的空間：一階一格n + 1 格，O(n)；每一格只看前兩格，只留兩個變數就能省到 O(1)

動態規劃跑幾步，通常是「表有幾格 × 每一格做多少事」。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

  2. 7

程式測試與除錯2. 想算 5 階有幾種走法（應該是 8），結果印出 0。要怎麼改？

C

int ways[6] = {0};
ways[1] = 1;
ways[2] = 2;
for (int i = 5; i >= 3; i--) {
    ways[i] = ways[i - 1] + ways[i - 2];
}
printf("%d\n", ways[5]);
  1. 把 ways[2] = 2 改成 ways[2] = 1
  2. 把陣列開大一格
  3. 把 ways[i - 2] 改成 ways[i - 1]
  4. 迴圈改成 i 從 3 往上數到 5

程式效能分析3. 用 calls 數 climb 被呼叫了幾次。加了記憶以後，下面這段程式跑完 climb(6)，印出的 calls 是多少？

C

int memo[10];
int calls = 0;

int climb(int n) {
    calls += 1;
    if (n <= 2) {
        return n;
    }
    if (memo[n] == 0) {
        memo[n] = climb(n - 1) + climb(n - 2);
    }
    return memo[n];
}

climb(6);
printf("%d\n", calls);
  1. 15
  2. 9
  3. 6
  4. 13

總結

14 階有 610 種走法，每天一種，可以連續走一年八個月不重複。下次碰到一個問題，答案可以拆成幾個小一點的同樣問題，而且那些小問題一直重複出現，你就知道：把答案填進表格，從小填到大。
