Binary Search on Answer　二分搜尋答案

生活應用

年底交換禮物，你要包 12 份，每份綁一條一樣長的緞帶。抽屜裡有四捲用剩的緞帶，長 750、620、480、390 公分，短的不能接起來用。每條最長可以剪多長？

複習

全部加起來 2240 公分，除以 12 是 186 公分？可是照 186 公分剪，四捲各剩一段零頭，只剪得出 4 + 3 + 2 + 2 = 11 條，還差一條。答案沒辦法直接除出來。

反過來就容易了：給一個長度，每捲除一下就知道剪得出幾條。用迴圈從 1 公分開始一公分一公分往上試，試到 161 公分第一次不夠 12 條，答案是 160，一共試了 161 次；緞帶換成幾公里長的電纜、單位換成公釐，就要試幾百萬次。 → 迴圈

我們學過二分搜尋：在排好的資料裡，每看一次中間就丟掉一半。這裡沒有陣列，可是「長度」本身就是從小排到大的：短的剪得出 12 條，更短的一定也剪得出；長的剪不出，更長的一定也剪不出。 → 搜尋

答案不好算，但好檢查：猜一個，檢查行不行，再決定往大的猜還是往小的猜。

核心觀念

二分搜尋答案（binary search on answer，也叫對答案二分）是不直接算答案，改成猜一個答案、檢查它行不行，再用二分搜尋把範圍一次砍掉一半。

能這樣做要有兩個條件。第一，檢查比直接算容易：給一個長度，每捲除一下、加起來，就知道夠不夠 12 條。第二，行不行是一刀切開的（單調性，monotonicity）：把 1 到 750 公分每個長度排成一列，前面一段都行、後面一段都不行，中間只有一個交界，答案就是最後一個行的。

寫法：lo、hi 夾住答案可能在的範圍，一開始 lo = 1、hi = 最長那捲的長度。每次猜 mid：行，答案在 mid 或更長，lo = mid；不行，答案比 mid 短，hi = mid − 1。lo 等於 hi 的時候，那個數就是答案。

找「最大的行」時，中間要取偏上的那個：mid = (lo + hi + 1) / 2。剩兩格的時候（lo = 159、hi = 160），不加 1 的 mid 永遠是 159，lo = mid 之後範圍沒有變小，迴圈停不下來。

題目問「最小的行」就反過來：mid = (lo + hi) / 2，行的話 hi = mid，不行的話 lo = mid + 1。

什麼時候會用到

  • 分工：一疊照順序排好的文件要分給 3 個人校對，每個人拿連續的一段。最忙的那個人最少要看幾頁？猜一個頁數上限，從頭開始分，看 3 個人分不分得完。
  • 一條路上有幾個可以裝路燈的位置，要裝 k 盞，想讓最近的兩盞盡量離遠一點。猜一個距離，從第一個位置開始，夠遠就裝，數裝不裝得下 k 盞。檢查的那一步每次都拿眼前能裝的，是貪婪法。 → 貪婪法
  • 開根號：沒有 sqrt 可以用的時候，猜一個數，平方太大就往小的猜。答案是小數也可以二分，猜到夠準就停。
  • APCS 實作題：題目問「最大值最小是多少」「最小值最大是多少」，多半是對答案二分。

常見誤解

誤解：對答案二分之前，要先把資料排序

正解：排好的不是資料，是答案的候選：1、2、3……公分本來就從小到大。四捲緞帶不用排序，要確認的是行不行有沒有一刀切開。

誤解：mid 一律寫 (lo + hi) / 2

正解：行的時候寫 lo = mid 的那種，中間要取偏上的 (lo + hi + 1) / 2；不然剩兩格時 mid 一直等於 lo，迴圈停不下來。

誤解：只要寫得出檢查，就可以對答案二分

正解：還要行不行是一刀切開的。例如問「哪個長度剪完剩下的零頭最少」，零頭隨長度忽多忽少，猜一個長度看不出該往長還是往短，不能二分。

誤解：lo 和 hi 抓個大概就好

正解：答案一定要落在 lo 到 hi 之間。hi 取最長那捲（再長連一條都剪不出）；lo 取 1 的前提是 1 公分一定剪得出 12 條；題目沒保證的話，lo 從 0 開始，最後答案是 0 就代表連 1 公分都剪不出來。

實作

C

#include <stdio.h>

// 每條剪 length 公分，n 捲緞帶一共剪得出幾條
int count_pieces(const int ribbons[], int n, int length) {
    int count = 0;
    for (int i = 0; i < n; i++) {
        count += ribbons[i] / length;
    }
    return count;
}

// 剪得出 need 條的最長長度；前提是 1 公分一定剪得出 need 條
int max_length(const int ribbons[], int n, int need) {
    int lo = 1, hi = 0;
    for (int i = 0; i < n; i++) {      // hi 取最長那捲：再長連一條都剪不出
        if (ribbons[i] > hi) {
            hi = ribbons[i];
        }
    }
    while (lo < hi) {
        int mid = (lo + hi + 1) / 2;   // 找最大的行：中間取偏上的
        if (count_pieces(ribbons, n, mid) >= need) {
            lo = mid;                  // 行：答案在 mid 或更長
        } else {
            hi = mid - 1;              // 不行：答案比 mid 短
        }
    }
    return lo;
}

int main(void) {
    int ribbons[] = {750, 620, 480, 390};
    printf("%d %d\n", max_length(ribbons, 4, 12), max_length(ribbons, 4, 5));
    return 0;
}

跑幾步

一公分一公分試答案是 A 就試 A + 1 次，每次看 n 捲，O(A × n)
對答案二分猜 log₂ M 次（M 是範圍的大小），每次看 n 捲，O(n log M)

750 公分猜 10 次；範圍到十億也只要 30 次。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

試試看

程式運行追蹤1. 三捲緞帶長 30、24、15 公分，要剪出 5 條一樣長的。下面這段程式印出什麼？

C

int ribbons[] = {30, 24, 15};
int need = 5;
int lo = 1, hi = 30;
while (lo < hi) {
    int mid = (lo + hi + 1) / 2;
    int count = ribbons[0] / mid + ribbons[1] / mid + ribbons[2] / mid;
    if (count >= need) {
        lo = mid;
    } else {
        hi = mid - 1;
    }
}
printf("%d\n", lo);

  2. 12
  3. 13
  4. 15

程式測試與除錯2. 同樣三捲緞帶 30、24、15 公分要剪 5 條，答案該是 12，下面這段程式卻印出 30。要怎麼改？

int ribbons[] = {30, 24, 15};

    int mid = (lo + hi + 1) / 2;
    int count = ribbons[0] / mid + ribbons[1] / mid + ribbons[2] / mid;

        hi = mid - 1;
    } else {
        lo = mid;

  1. 把 mid 改成 (lo + hi) / 2
  2. 把 hi 一開始的值改成 15
  3. 把兩個分支對調：夠的時候 lo = mid，不夠的時候 hi = mid − 1
  4. 把 count >= need 改成 count > need

總結

每條最長 160 公分。不用從 1 公分試到 161 公分：猜中間的長度，剪得出 12 條就往長的猜，剪不出就往短的猜，750 公分的範圍猜 10 次就夠。下次碰到「最多可以多少」「最少要多少」的問題，可以先問自己兩件事：猜一個答案，檢查它行不行容不容易？是不是小的都行、大到某個地方之後都不行？兩個都是，就對答案二分。

課外補充

答案是小數也可以二分。沒有 sqrt 的時候算 2 的平方根：lo = 0、hi = 2，每次猜 mid = (lo + hi) / 2，mid × mid 超過 2 就 hi = mid，不然 lo = mid。小數沒有「下一個數」，所以不用加 1、減 1；lo 和 hi 也很難剛好相等，所以不用 lo < hi 當條件，改成固定猜 100 次，或猜到兩邊差距小於要的精確度就停。每猜一次範圍剩一半：猜 20 次，lo 和 hi 的差距不到 0.00001，兩邊都是 1.41421 開頭。
