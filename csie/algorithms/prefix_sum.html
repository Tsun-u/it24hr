Prefix Sum　前綴和

生活應用

手機的健康 App 記了你每天走幾步。點開它，這週、上個月、今年到現在，任何一段日子的總步數一下就跳出來。它是每問一次，就把那段日子從頭加一遍嗎？

複習

我們學過陣列和迴圈：每天的步數存在陣列 steps，第 a 天到第 b 天的總和，就用迴圈把那幾天一天一天加起來。查一次最多加 365 次。可是 App 一直被問：這週、上週、這個月、今年……問 1000 次就是最多 36 萬次加法，而且大部分是在重複加同樣的那幾天。 → 陣列與串列→ 迴圈

任何一段的總和，都等於兩個「從第一天加到這裡」的總數相減。

核心觀念

前綴和（prefix sum）是先把累計算好存起來的另一個陣列 pre：pre[i] 是前 i 天加起來的總數。從左往右填，每一格是左邊那格加上那一天：pre[i] = pre[i − 1] + 第 i 天的步數。七天的步數 3、1、4、1、5、9、2，pre 就是 0、3、4、8、9、14、23、25。程式裡的陣列從 0 數，所以第 i 天是 steps[i − 1]。

第 a 天到第 b 天的總和＝pre[b] − pre[a − 1]。跟看汽車的里程表一樣：出發前看一次、到了再看一次，相減就是這趟開了幾公里，不用一段一段加。pre[b] 是前 b 天，pre[a − 1] 是前 a − 1 天，減掉以後剩下的剛好是第 a 天到第 b 天。圖解裡第 3 到第 5 天：14 − 4 = 10。

pre 比原本的陣列多一格：pre[0] = 0，代表「前 0 天」什麼都還沒加。這樣從第 1 天開始問的時候，一樣是 pre[b] − pre[0]，不用另外寫 if。

這是拿空間換時間：多用一個陣列、先花 n 次加法把表建好，之後每問一段都只要一次減法。名字裡的 prefix 是「前綴」，指從開頭到某個位置的那一段。

什麼時候會用到

  • 存摺上的餘額就是一路累計下來的總數：想知道 3 月初到 5 月底淨進出多少錢，拿 5 月底的餘額減 2 月底的餘額就好，不用把中間每一筆加起來。
  • 用試算表記帳時，常在旁邊多開一欄「累計」：每一格是上一格加這一列。要看任何一段的總計，兩格相減。
  • 影像處理的積分影像（integral image）：每一格存左上角到這裡所有像素的總和，任何一塊長方形的亮度總和用四個數就算完。2001 年發表的即時人臉偵測（Viola–Jones）就是靠它，在一張照片裡快速檢查大量的框框。
  • APCS 實作題：同一個陣列要回答很多次「某一段的總和」；或是「總和剛好是 k 的連續區段有幾段」，前綴和搭配雜湊表，從頭掃一次就數完。 → 雜湊

常見誤解

誤解：第 a 天到第 b 天的總和是 pre[b] − pre[a]

正解：這樣會少掉第 a 天：pre[a] 已經包含第 a 天，減掉它就從第 a + 1 天開始算了。要減的是 pre[a − 1]，前 a − 1 天。

誤解：前綴和的陣列跟原本的陣列一樣長就好

正解：要多一格放 pre[0] = 0。少了它，從第 1 天開始問的時候就得另外寫 if，不然會讀到陣列外面：C、C++ 讀到不知道是什麼的值，Java 直接報錯，Python 的 pre[-1] 不會報錯、拿到的是最後一格，答案錯得很安靜。

誤解：資料改了一天，前綴和改那一格就好

正解：第 i 天改了，pre[i] 到最後一格全部都要重算。資料常常在改、又常常要問總和的時候，前綴和就不划算，要換成樹狀陣列、線段樹這類進階的結構。

誤解：前綴和什麼都能算，最大值也可以

正解：要能「減回去」才行：總和、次數可以兩個相減；最大值不行。前 5 天最大是 5、前 2 天最大是 3，相減得到的 2，跟第 3 到第 5 天的最大值 5 沒有關係。

誤解：累計的總數用 int 一定裝得下

正解：int 最大大約 21 億。一年的步數加起來沒問題；可是 APCS 常見 20 萬個數、每個到 10 億，累計會超過 int 的上限。C、C++ 要用 long long、Java 用 long，Python 的整數沒有上限。

實作

C

#include <stdio.h>

// pre[i] 是前 i 天的總和，pre[0] = 0
void build_prefix(const int steps[], int n, int pre[]) {
    pre[0] = 0;
    for (int i = 1; i <= n; i++) {
        pre[i] = pre[i - 1] + steps[i - 1];
    }
}

// 第 a 天到第 b 天（從 1 數）的總和
int range_sum(const int pre[], int a, int b) {
    return pre[b] - pre[a - 1];
}

int main(void) {
    int steps[] = {3, 1, 4, 1, 5, 9, 2};
    int pre[8];
    build_prefix(steps, 7, pre);
    printf("%d %d %d\n", range_sum(pre, 3, 5), range_sum(pre, 1, 7), range_sum(pre, 6, 6));
    return 0;
}

def build_prefix(steps):                 # pre[i] 是前 i 天的總和，pre[0] = 0
    pre = [0] * (len(steps) + 1)

跑幾步

每問一段都從頭加：一段最長 n 天一次最多 n 次加法，O(n)
先建前綴和：迴圈跑 n 圈，每圈一次加法n 次，O(n)，只做一次
建好以後每問一段：一次減法O(1)
問 q 次合起來每次從頭加 O(n × q)；前綴和 O(n + q)

一年 365 天、問 1000 次：每次從頭加最多 36 萬多次加法，前綴和是 365 次加法加 1000 次減法。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

總結

App 不用每次從頭加：它先存好每天「到今天為止」的累計步數，任何一段都是兩個數相減，一年問幾次都只要一次減法。下次碰到同一份資料要一直問某一段的總和，你就知道：先花一次把累計算好存起來，之後每一問都只剩一次減法。

課外補充

二維前綴和：試算表、照片這種格子資料，pre[i][j] 存左上角到第 i 列第 j 行這一塊的總和。任何一塊長方形的總和，用四個數加加減減就算完：右下角那格，減掉上面那塊、減掉左邊那塊，再把左上角被扣了兩次的那塊加回來。用途裡的積分影像就是它。

差分陣列（difference array）：前綴和反過來用。要把一整段日子都加上同一個數（第 3 到第 5 天每天多 2 千步），不用一天一天改，只在第 3 天記 +2、第 6 天記 −2，最後對這些記號做一次前綴和，每一天該加多少就都出來了。適合「改很多次、最後才看結果」的題目。
