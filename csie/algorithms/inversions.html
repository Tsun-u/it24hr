Counting Inversions　逆序數對

生活應用

一套 8 集的漫畫在書架上被放成 3、1、4、8、2、6、5、7。每次只能把相鄰的兩本對調，最少要調幾次，才能排回第 1 集到第 8 集？

複習

要調的次數，剛好等於「集數大的排在集數小的前面」有幾對，這種一對叫逆序數對（inversion）。用兩層迴圈一對一對看，8 本有 28 對；十萬筆資料就是將近 50 億對。 → 迴圈

分治法那頁的課外補充寫過遞迴版的合併排序。 → 分治法

左半、右半各自排好之後，右半的數每搶先一次，就一次跨過左半還沒拿的全部。

核心觀念

逆序數對（inversion）：一排數字裡，前面的比後面的大，這樣的一對。排好的有 0 對；完全倒過來的，每一對都是，有 n(n − 1) / 2 對。

為什麼相鄰對調的次數等於逆序數對：對調一對相鄰、而且順序反了的書，逆序數對剛好少 1，別的書之間誰前誰後都沒變。所以至少要調這麼多次；每次都找一對相鄰又反了的來調，也剛好這麼多次。

用分治法數：切成左右兩半之後，每一對只有三種：兩本都在左半、兩本都在右半、一本在左一本在右。前兩種交給遞迴，第三種在合併的時候數。 → 分治法

合併的時候怎麼數：左右兩半各自排好了。右半現在這一本比左半現在這一本小，就先拿右半的；左半還沒拿的每一本都比它大（因為排好了），這幾本跟它都是逆序，一次加上「左半還剩幾本」。

兩半各自排好，不會把答案弄亂：排的是半邊裡面的順序，一左一右的每一對，誰在左、誰在右沒有變。

什麼時候會用到

  • 比兩份排行榜差多少：把朋友的排名照你的順序重新編號，逆序數對越多，兩個人的口味差越多。統計學叫它 Kendall tau 距離。
  • 氣泡排序要交換幾次，就是逆序數對有幾對。 → 排序
  • 衡量一份資料「有多亂」：0 對是已經排好，n(n − 1) / 2 對是完全倒過來。
  • APCS 實作題：資料到十萬筆，兩層迴圈會超過時間，要用合併排序邊排邊數。

常見誤解

誤解：兩個一樣大的數也算一對

正解：不算，要前面的比後面的大才算。合併時兩邊一樣大要先拿左半的（比較寫 <=），不然一樣大的會被算進去。

誤解：合併時，拿左半的那一刻加上右半剩下的

正解：是拿右半的那一刻，加上左半還沒拿的個數（試試看第二題）。

誤解：對數用 int 裝得下

正解：十萬筆最多有將近 50 億對，超過 int 的上限。C、C++ 用 long long，Java 用 long。

誤解：數完之後陣列還是原來的樣子

正解：邊數邊排，數完陣列已經排好了。原本的順序還要用的話，先複製一份。

實作

C

#include <stdio.h>

// 數 data[left..right] 裡有幾對逆序數對，順便把這一段排好
long long count_inversions(int data[], int left, int right) {
    if (left >= right) {                     // 只剩一個數：湊不成一對
        return 0;
    }
    int mid = (left + right) / 2;
    long long count = count_inversions(data, left, mid);   // 兩個都在左半的
    count += count_inversions(data, mid + 1, right);       // 兩個都在右半的
    int merged[right - left + 1];            // 一個在左、一個在右的：合併的時候數
    int i = left, j = mid + 1, k = 0;
    while (i <= mid && j <= right) {
        if (data[i] <= data[j]) {            // 一樣大先拿左半的，一樣大的才不會被算進去
            merged[k++] = data[i++];
        } else {
            count += mid - i + 1;            // 先拿右半的：左半還沒拿的每一個都比它大
            merged[k++] = data[j++];
        }
    }
    while (i <= mid) {                       // 左半還有剩：整段接上去
        merged[k++] = data[i++];
    }
    while (j <= right) {                     // 右半還有剩：整段接上去
        merged[k++] = data[j++];
    }
    for (int t = 0; t < k; t++) {            // 把合好的結果放回原本的位置
        data[left + t] = merged[t];
    }
    return count;
}

int main(void) {
    int shelf[] = {3, 1, 4, 8, 2, 6, 5, 7};
    int backwards[] = {8, 7, 6, 5, 4, 3, 2, 1};
    long long first = count_inversions(shelf, 0, 7);
    long long second = count_inversions(backwards, 0, 7);
    printf("%lld %lld\n", first, second);
    return 0;
}

Python

def count_inversions(data, left, right):    # 數 data[left..right] 裡有幾對逆序數對，順便把這一段排好
    if left >= right:                       # 只剩一個數：湊不成一對
        return 0
    mid = (left + right) // 2
    count = count_inversions(data, left, mid)         # 兩個都在左半的
    count += count_inversions(data, mid + 1, right)   # 兩個都在右半的
    merged = []                             # 一個在左、一個在右的：合併的時候數
    i, j = left, mid + 1
    while i <= mid and j <= right:
        if data[i] <= data[j]:              # 一樣大先拿左半的，一樣大的才不會被算進去
            merged.append(data[i])
            i += 1
        else:
            count += mid - i + 1            # 先拿右半的：左半還沒拿的每一個都比它大
            merged.append(data[j])
            j += 1
    while i <= mid:                         # 左半還有剩：整段接上去
        merged.append(data[i])
        i += 1
    while j <= right:                       # 右半還有剩：整段接上去
        merged.append(data[j])
        j += 1
    for t in range(len(merged)):            # 把合好的結果放回原本的位置
        data[left + t] = merged[t]
    return count

跑幾步

兩層迴圈一對一對看n(n − 1) / 2 對，O(n²)
合併排序邊排邊數O(n log n)

十萬筆是將近 50 億對，對上大約 170 萬步。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

試試看

程式運行追蹤1. 左半 3、6、7、9 和右半 1、4、5、8 都排好了，合併的時候順便數逆序數對。下面這段程式印出什麼？

C

int left[] = {3, 6, 7, 9};
int right[] = {1, 4, 5, 8};
int i = 0, j = 0, count = 0;
while (i < 4 && j < 4) {
    if (left[i] <= right[j]) {
        i += 1;
    } else {
        count += 4 - i;
        j += 1;
    }
}
printf("%d\n", count);
  1. 4
  2. 5
  3. 7
  4. 11

程式測試與除錯2. 左半 2、5、8 和右半 1、4、6 合併，應該數到 6 對，這段程式卻印出 3。要怎麼改？

C

int left[] = {2, 5, 8};
int right[] = {1, 4, 6};
int i = 0, j = 0, count = 0;
while (i < 3 && j < 3) {
    if (left[i] <= right[j]) {
        count += 3 - j;
        i += 1;
    } else {
        j += 1;
    }
}
printf("%d\n", count);
  1. 把 <= 改成 <
  2. 把 count += 3 - j 移到 else 那一邊，改成 count += 3 - i
  3. 把 count += 3 - j 改成 count += 3 - i，位置不動
  4. 把 count += 3 - j 移到 else 那一邊，改成 count += 1

解析計算邏輯3. 這次兩半裡有一樣大的數：左半 2、5、5，右半 2、5、7，真正的逆序數對只有 2 對。這段程式的比較寫成了 <，它印出多少？

總結

最少要調 8 次。不用真的去調，也不用 28 對一對一對看：切兩半各自數，合併的時候右半每拿一個，就把左半剩下的個數一次加上去。下次碰到「數有幾對順序反了」，像比兩份排行榜差多少，你就知道：邊排序邊數，一次數一整批。

課外補充

換一個角度也數得出來：從左到右一個一個看，問「前面有幾個比我大」。這個問法用樹狀陣列（Fenwick tree）也能做到 O(n log n)，那是進階的資料結構，這裡只提名字。
