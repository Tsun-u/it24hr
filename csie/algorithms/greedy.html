Greedy　貪婪法

生活應用

影展這天有 8 場電影你都想看，場次的時間互相重疊。想看到最多場，你會先挑哪一場：最早開演的、片長最短的，還是最早散場的？

複習

用前面學過的回溯，可以每一場選或不選全部試過：8 場有 256 種，挑出時間不重疊、場數最多的那一種。影展一個週末有 50 場，2 的 50 次方種試不完。 → 回溯

人不會這樣排。我們會定一個規則，照規則一場一場挑下去，挑了就不改。問題是哪個規則才對。

每一步都拿眼前最好的那個，拿了就不回頭。

核心觀念

貪婪法（greedy algorithm）是每一步都拿眼前最好的選擇，拿了就不改，一路做到完。它不回頭，所以快；也因為不回頭，一開始的規則要選對。

排場次的規則：把場次照散場時間從早到晚排好，從頭看下去，開演時間不早於「上一場散場的時間」就挑，然後把那個時間更新成這一場的散場時間。

為什麼先挑最早散場的不會吃虧：假設有一種最好的排法，第一場不是最早散場的那場。把它的第一場換成最早散場的那場，新的第一場更早結束，後面每一場照樣趕得上，場數一樣多。所以「先挑最早散場的」至少跟最好的排法一樣好。剩下的時間是同一個問題，再挑一次。

貪婪法不是每個問題都能用，要說得出這種「換過來也不會變差」的理由。說不出來、又舉得出反例，就不能用：最早開演的那場可能是一部 6 小時的長片；片長最短的那場可能剛好卡在兩場中間。

跟另外兩種方法比：回溯把選擇全部試過，一定對但慢；動態規劃把每個小問題最好的答案記下來，對，可是要一張表；貪婪法只走一條路，最快，前提是先確定這條路走得到最好的答案。 → 回溯→ 動態規劃

什麼時候會用到

  • 找零錢：找 87 元，先拿 50 元，再拿三個 10 元、一個 5 元、兩個 1 元。台幣的面額可以每次先拿最大的。
  • 訂會議室：一間會議室一天想排進最多場會議，就是這一頁的問題。
  • 圖的演算法：最小生成樹每次挑最短、又不會繞成圈的那條邊；最短路徑每次確定離起點最近的那個點。 → 最小生成樹→ 最短路徑
  • 壓縮檔案的霍夫曼編碼（Huffman coding）：每次把出現次數最少的兩個符號合在一起，常出現的符號就會分到比較短的代碼。
  • APCS 實作題：先排序，再從頭一個一個決定要不要拿的題目。

常見誤解

誤解：每一步都拿最好的，最後的結果一定最好

正解：眼前最好不一定整體最好。硬幣面額如果是 1、4、5 元，要湊 8 元：每次先拿最大的是 5 + 1 + 1 + 1 四個，可是 4 + 4 兩個就夠。這種面額要用動態規劃。 → 動態規劃

誤解：排場次，先挑片長最短的也可以

正解：這一頁的 8 場照片長挑只看得到 3 場：12–14 和 18–20 這兩場短片，各卡在兩場本來可以接著看的電影中間。照最早開演挑也是 3 場，9–15 那場一口氣擋掉四場。

誤解：貪婪法不用排序

正解：多半要先排序，才能從頭一個一個挑。排序是 O(n log n)，挑的那一趟只有 O(n)，所以時間幾乎都花在排序。

誤解：開演時間等於上一場的散場時間，算不算重疊都沒差

正解：差一個等號，答案可能差一場。這一頁算可以接著看（start >= free）；題目說要留換場時間的話，條件就不一樣，要照題目寫。

實作

C

#include <stdio.h>

// 數最多看得到幾場；場次要照散場時間從早到晚排好（還沒排的話要先排序），arrive 是到影展的時間
int max_sessions(const int start[], const int end[], int n, int arrive) {
    int free = arrive, count = 0;   // free：上一場散場的時間，一開始是到影展的時間
    for (int i = 0; i < n; i++) {
        if (start[i] >= free) {     // 開演時間不早於上一場散場：趕得上，挑
            count++;
            free = end[i];
        }
    }
    return count;
}

int main(void) {
    int start[] = {10, 12, 9, 13, 14, 16, 18, 19};
    int end[] = {13, 14, 15, 16, 17, 19, 20, 22};
    printf("%d %d\n", max_sessions(start, end, 8, 9), max_sessions(start, end, 8, 14));
    return 0;
}

跑幾步

回溯每場選或不選O(2ⁿ)
貪婪排序 O(n log n)，加上挑一趟 O(n)

50 場的話，2 的 50 次方大約是一千兆；排序加挑一趟只要幾百步。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

程式運行追蹤1. 一間會議室收到 6 場會議的申請，已經照結束時間排好，想排進最多場。下面這段程式印出什麼？

程式測試與除錯2. 影展那 8 場，這次資料是照開演時間排的。程式印出 3，可是明明可以看 4 場。要怎麼改？

C

int start[] = {9, 10, 12, 13, 14, 16, 18, 19};
int end[] = {15, 13, 14, 16, 17, 19, 20, 22};
int free = 0, count = 0;
for (int i = 0; i < 8; i++) {
    if (start[i] >= free) {
        count += 1;
        free = end[i];
    }
}
printf("%d\n", count);
  1. 把 start[i] >= free 改成 start[i] > free
  2. 把場次改成照散場時間排好，再用同一段程式挑
  3. 把 free = end[i] 改成 free = start[i]
  4. 把 free = end[i] 移到 if 外面，每一場都更新

解析計算邏輯3. 硬幣面額是 5、4、1 元，下面這段找零程式每次先拿最大的面額。要湊 8 元，它印出用了幾個硬幣？

C

int coins[] = {5, 4, 1};
int amount = 8, count = 0;
for (int i = 0; i < 3; i++) {
    while (amount >= coins[i]) {
        amount -= coins[i];
        count += 1;
    }
}
printf("%d\n", count);
  1. 2
  2. 3
  3. 4
  4. 8

總結

先挑最早散場的：它最早把時間還給你，留給後面的場次最多。這 8 場最多看得到 4 場；先挑最早開演或片長最短的，都只看得到 3 場。下次碰到要一步一步挑的問題，可以先找找看有沒有一個「眼前最好」的挑法，挑了之後不會後悔。有，照著挑就是貪婪法；舉得出反例，就回去用回溯或動態規劃。

課外補充

背包能不能用貪婪，看東西能不能切。能切的（散裝的茶葉、米）每次先拿每公斤最值錢的，裝到滿為止，是貪婪法；不能切的（一整台相機）這樣拿可能留下塞不滿的空間，要用動態規劃。 → 動態規劃
