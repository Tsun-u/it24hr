Backtracking　回溯

生活應用

搭車回家，還有 20 分鐘到站。你想從歌單的 12 首歌裡挑幾首，剛好在到站的時候播完。每首歌選或不選，12 首一共有 4096 種挑法，要一種一種加起來看嗎？

複習

用學過的遞迴，可以把每一種挑法都走到：每首歌分成「選」和「不選」兩條路，12 首走到底有 4096 種，每一種加起來看是不是 20 分鐘。把所有可能都列出來檢查，叫暴力法（brute force），也叫窮舉。30 首歌就超過十億種。 → 遞迴

可是你自己挑歌的時候不會這樣。前四首加起來已經 22 分鐘，後面八首不管怎麼挑都超過，這 256 種挑法一種都不用看。

挑到一半發現不可能了，就退回上一步，換另一個選擇。

核心觀念

回溯（backtracking）是一步一步做選擇，每做一個就檢查：還有可能，就往下一步；已經不可能，就退回上一步、換下一個選擇；這一步的選擇全部試完都不行，再往前退一步。

把所有選擇畫出來是一棵樹：每一層是一首歌，往左是選、往右是不選，從頂走到底的每一條路是一種挑法。暴力法把每條路都走到底才檢查；回溯在半路檢查，不可能的那一整枝都不走，這叫剪枝（pruning）。

寫成遞迴：pick(i, total) 是「前 i 首決定好了，目前加到 total 分鐘」。先試選第 i 首，呼叫 pick(i + 1, total + songs[i])；回來的答案是不行，再試不選，呼叫 pick(i + 1, total)。每一層有自己的 total，回到上一層，剛才加的那首自然就不算了，這就是「退回」。 → 遞迴

什麼時候停：加起來剛好是目標，找到了；歌都決定完了，或已經超過目標，這條路不行。「超過就不用往下」能成立，是因為歌的長度都是正的，越加只會越多。

兩種常見的形狀。子集合：每樣東西選或不選，n 樣有 2ⁿ 種，這一頁就是。排列：每個位置放誰，n 個有 n! 種，要多一個陣列記誰已經放過了，退回時把記號改回來。

什麼時候會用到

  • 數獨：填到一半發現同一列已經有 5，把剛填的擦掉、換一個數字；每個數字都不行，就再往前擦一格。
  • 走迷宮：碰到死路，退回上一個岔路口，換一條還沒走過的路。圖的深度優先搜尋也是這樣走。 → 圖
  • 排座位、排班表：一個位置一個位置放人，放下去跟前面衝突就換人。每個位置「放誰」是一個選擇，n 個人有 n! 種排法。
  • APCS 實作題：列出所有排列、所有子集合，再照題目的限制提早放棄；經典題是八皇后（8 個皇后放上西洋棋盤，互相吃不到）。 → 八皇后

常見誤解

誤解：回溯和暴力法一樣，都是全部試一遍

正解：暴力法每條路走到底才檢查；回溯走一步檢查一步，不可能的整枝不走。最壞的情況（沒有東西可以剪）兩個一樣慢，差在平常能剪掉多少。

誤解：找到答案的時候 return，整個遞迴就停了

正解：return 只回到上一層。上一層要接住回傳值，是「找到了」就自己也馬上 return，一層一層傳上去；沒接住的話會繼續試別的選擇。

誤解：用陣列記選了哪些，遞迴回來之後記號會自己恢復

正解：陣列傳進函式，改的是同一份。選的時候記 1，回來之後要自己改回 0，不然上一條路留下的記號會混進下一條路（試試看第二題）。total 這種一般的變數每一層各有一份，才不用改。 → 傳值與傳參考

誤解：剪枝的條件多加幾個，只會更快

正解：剪錯會把答案剪掉。「超過目標就放棄」在長度都是正數時才對；題目裡有負數（例如折扣）的話，超過了之後還可能減回來。

實作

C

#include <stdio.h>

int songs[] = {6, 5, 4, 7, 3, 8, 5, 4, 6, 3, 7, 4};
int n = 12;
int target = 20;
int chosen[12];                         // chosen[i] 是 1 代表選了第 i 首，一開始全部是 0

// 前 i 首決定好了，目前加到 total 分鐘；湊得到 target 回傳 1，湊不到回傳 0
int find(int i, int total) {
    if (total == target) {              // 剛好：找到了
        return 1;
    }
    if (i == n || total > target) {     // 歌都決定完了，或已經超過：這條路不行
        return 0;
    }
    chosen[i] = 1;                      // 選第 i 首
    if (find(i + 1, total + songs[i]) == 1) {
        return 1;                       // 後面湊到了：自己也馬上回傳，一層一層傳上去
    }
    chosen[i] = 0;                      // 退回：把記號改回來
    return find(i + 1, total);          // 換成不選第 i 首
}

int main(void) {
    if (find(0, 0) == 1) {
        for (int i = 0; i < n; i++) {
            if (chosen[i] == 1) {
                printf("%d ", songs[i]);
            }
        }
        printf("\n");
    } else {
        printf("none\n");
    }
    return 0;
}

跑幾步

暴力法：2ⁿ 種挑法，每種加 n 首O(2ⁿ × n)
回溯：實際看剪掉多少（12 首湊 20 分鐘：走 25 步就找到第一組；要數出全部 89 組，超過就退回要走 2271 步，每條路都走到底是 8191 步）最壞還是 O(2ⁿ)
排列型：每個位置放誰O(n!)

n 每多 1，暴力法的挑法就變兩倍；題目的 n 通常給得很小（20 上下），就是在暗示可以用回溯。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

程式運行追蹤1. 三首歌 5、4、3 分鐘，想湊剛好 7 分鐘；chosen 記選了哪幾首。下面這段程式印出什麼？

int songs[] = {5, 4, 3};

    if (total == 7) {

程式效能分析3. 這個版本不剪枝：4 首歌每一種挑法都走到底，才看加起來是不是 7 分鐘；calls 數 walk 被呼叫了幾次。下面這段程式印出的 calls 是多少？

C

int songs[] = {5, 4, 3, 2};
int calls = 0;
int ways = 0;

void walk(int i, int total) {
    calls += 1;
    if (i == 4) {
        if (total == 7) {
            ways += 1;
        }
        return;
    }
    walk(i + 1, total + songs[i]);
    walk(i + 1, total);
}

walk(0, 0);
printf("%d\n", calls);
  1. 16
  2. 15
  3. 31
  4. 24

總結

不用把 4096 種都加一遍：一首一首決定選或不選，加起來超過 20 分鐘就退回上一步，那首歌後面的挑法一次全部跳過。這份歌單只走了 25 步就找到 6、5、4、5 分鐘這四首。下次碰到要一步一步做選擇的問題，像排座位、填數獨，你就知道：走一步檢查一步，走不通就退回上一個選擇，換一條路。

課外補充

排列型的回溯：6 個人坐一排、同一家的不坐隔壁，一個位置一個位置放人，used 陣列記誰坐下了；放下去隔壁是同一家就換人，後面坐不下去就請剛坐下的人起來（used 改回來）。6 個人有 720 種坐法，每放一個就檢查，不用排完整排才知道不行。
