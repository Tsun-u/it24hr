Two Pointers　雙指標

生活應用

百貨公司的禮券不找零。你手上有一張 1000 元的禮券，想買兩樣東西剛好用完。架上 50 樣商品已經照價錢從便宜排到貴，一對一對加起來試，最多要試 1225 對。有沒有更快的找法？

複習

我們學過巢狀迴圈：外層挑第一樣、內層挑第二樣，加起來剛好 1000 就找到了。50 樣最多 1225 對；換成網購平台上一萬樣商品，就是將近五千萬對。可是價錢明明已經排好了，很多對根本不用加就知道不可能：最貴的那樣配上最便宜的都超過 1000，它跟誰配都超過。 → 迴圈

加起來太多，就把貴的那邊換便宜一點；不夠，就把便宜的那邊換貴一點。

核心觀念

雙指標（two pointers）是用兩個索引在陣列上移動，取代兩層迴圈把每一對都試一遍。這一頁的版本是從兩頭往中間收：left 從最左邊（最便宜）出發，right 從最右邊（最貴）出發。這裡的「指標」是指著某一格的位置，不是 C 語言的指標（pointer）。

每一步看 prices[left] + prices[right]：剛好等於目標，就找到了；太多，right 往左一格，換便宜一點的；不夠，left 往右一格，換貴一點的。left 碰到 right 還沒找到，就是沒有這樣的一對。

為什麼可以這樣跳過？加起來太多的時候，最貴的 prices[right] 配上目前最便宜的 prices[left] 都太多，配上 left 右邊更貴的只會更多，所以它跟誰都配不成，可以整個排除。不夠的時候反過來，排除 prices[left]。每一步排除一樣商品，所以 n 樣最多走 n − 1 步。

前提是陣列要先照大小排好，「太多就往左」才有意義。資料還沒排好的話，先排序再用雙指標。 → 排序

什麼時候會用到

  • 檢查一句話是不是迴文（正著讀、倒著讀都一樣，像「上海自來水來自海上」）：一根手指從頭、一根從尾，一起往中間比，有一對不一樣就不是。
  • 把兩份排好的名單合成一份：兩邊各放一根手指，每次拿比較小的那個、那根手指往後一格。合併排序的「合併」就是這樣做。 → 排序
  • 三個數加起來剛好是目標（3Sum）：先固定第一個數，剩下的兩個就變成這一頁的問題，用雙指標找。
  • APCS 實作題：排好序的陣列裡找「和剛好是 k 的一對」、「和最接近 k 的一對」，或是數「差不超過 k 的有幾對」。

常見誤解

誤解：雙指標在還沒排序的陣列上也能用

正解：要排好序，「加起來太多，往左就會變少」才成立。沒排序的陣列往左一格不一定比較便宜，會把答案跳過去。先排序（O(n log n)）再用雙指標，還是比兩層迴圈的 O(n²) 快。

誤解：加起來太多的時候，left 往右也可以

正解：left 往右是換成更貴的，總和只會更多。要讓總和變少，只能把 right 往左。兩邊移錯，就會直接走過頭（試試看第二題）。

誤解：迴圈的條件寫 left <= right 比較保險

正解：left 等於 right 的時候，兩根手指指著同一樣商品，等於拿它跟自己配。題目要兩樣不同的東西，條件要寫 left < right。

誤解：找到一對就可以停，題目問「有幾對」也一樣

正解：要數全部的話，找到一對之後 left、right 都往內收一格，繼續找下一對；價錢有重複時還要另外處理同價的那幾格。實作的 count_pairs 就是數全部的版本。

實作

C

#include <stdio.h>

// 數有幾對加起來剛好是 target；prices 要先照小到大排好，而且沒有重複的價錢
int count_pairs(const int prices[], int n, int target) {
    int left = 0, right = n - 1, count = 0;
    while (left < right) {
        int total = prices[left] + prices[right];
        if (total == target) {        // 找到一對：兩邊都往內收，繼續找下一對
            count++;
            left++;
            right--;
        } else if (total > target) {  // 太多：換便宜一點的
            right--;
        } else {                      // 不夠：換貴一點的
            left++;
        }
    }
    return count;
}

int main(void) {
    int prices[] = {150, 260, 340, 480, 520, 660, 740, 790, 850};
    printf("%d %d\n", count_pairs(prices, 9, 1000), count_pairs(prices, 9, 1110));
    return 0;
}

跑幾步

兩層迴圈把每一對都試一遍n(n − 1) / 2 對，O(n²)
雙指標：每一步排除一樣，兩根手指碰在一起就停最多 n − 1 步，O(n)
資料還沒排好，要先排序O(n log n)，排完再加上雙指標的 O(n)

50 樣商品：兩層迴圈最多 1225 對，雙指標最多 49 步；一萬樣是將近五千萬對比 9999 步。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

試試看

程式運行追蹤1. 六樣商品照價錢排好，想找兩樣加起來剛好 750 元。下面這段程式印出什麼？

C

int prices[] = {120, 200, 310, 430, 550, 680};
int left = 0, right = 5;
while (left < right) {
    int total = prices[left] + prices[right];
    if (total == 750) {
        break;
    } else if (total > 750) {
        right -= 1;
    } else {
        left += 1;
    }
}
printf("%d %d\n", prices[left], prices[right]);
  1. 120 680
  2. 200 550
  3. 310 430
  4. none

程式測試與除錯2. 同樣六樣商品找 750 元，明明有 200 + 550，程式卻印出 none。要怎麼改？

C

int prices[] = {120, 200, 310, 430, 550, 680};
int left = 0, right = 5;
while (left < right) {
    int total = prices[left] + prices[right];
    if (total == 750) {
        break;
    } else if (total > 750) {
        left += 1;
    } else {
        left += 1;
    }
}
if (left < right) {
    printf("%d %d\n", prices[left], prices[right]);
} else {
    printf("none\n");
}
  1. 把 left < right 改成 left <= right
  2. 加起來太多的時候，改成 right 往左一格
  3. 把 left 一開始的值改成 1
  4. 把 total == 750 改成 total >= 750

程式效能分析3. prices 是 0、1、2、……、999 共 1000 個數，已經排好；target 是 5000，再怎麼加都不夠。left 從 0、right 從 999 出發，下面這段程式印出的 steps 是多少？

總結

不用試 1225 對：一根手指放最便宜、一根放最貴，加起來太多就把貴的換便宜一點，不夠就把便宜的換貴一點，每看一次就排除一整排，50 樣最多看 49 次就知道有沒有。下次碰到「排好序的資料裡找一對」，你就知道：兩頭各放一根手指往中間收，不用每一對都試。

課外補充

滑動視窗（sliding window）：兩根手指往同一個方向走。例如每天的步數記在陣列裡，問「連續幾天加起來至少 2 萬步，最少要幾天」：右手指一天一天往右，把那天加進總和；總和夠了，就把左手指往右收，看能不能更短。每一天最多被加進來一次、減出去一次，所以也是 O(n)。能這樣收的前提是步數不會是負的，收掉一天總和一定變少。 → 前綴和
