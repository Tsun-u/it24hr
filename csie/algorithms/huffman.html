Huffman Coding　霍夫曼編碼

生活應用

把一份全是文字的報告壓成 zip，檔案剩不到一半；解壓縮之後，一個字都沒少。少掉的那一半去哪了？

複習

電腦裡每個英文字母都用一樣長的代碼。一則 15 個字的訊息只用到 A、B、C、D、E 五種字母，每個字母 3 個位元，一共 45 個位元。可是 A 出現了 7 次，E 只出現 1 次，兩個卻佔一樣長。

貪婪法每一步拿眼前最好的；每次要拿「最小的兩個」，用堆積最快。 → 貪婪法→ 堆積

常出現的給短代碼，少出現的給長代碼；每次把出現最少的兩個合成一組。

核心觀念

霍夫曼編碼（Huffman coding）是 David Huffman 在 1952 年發表的，當時他還是麻省理工學院的研究生。它給每個符號一個長短不一的代碼：越常出現的越短。

建樹：每個符號先各自是一個節點，記著它出現幾次。每次挑次數最少的兩個，合成一個新的節點，次數是兩個相加，放回去再挑。合到只剩一個，它就是樹根。 → 樹

代碼怎麼來：從樹根走到那個符號，往左記 0、往右記 1。常出現的符號比較晚被合進去，離樹根近，代碼就短。

符號都在葉子上，所以沒有一個代碼會是另一個代碼的開頭，這叫前綴碼（prefix code）。解碼時從樹根照著位元往下走，走到葉子就是一個符號，再回樹根接著走，中間不用放分隔的記號。

編完一共幾個位元，等於每次合併出來的次數全部加起來：2 + 4 + 8 + 15 = 29。

「每次拿最小的兩個」用堆積來做，n 個符號是 O(n log n)。為什麼每次合最少的兩個就是最好的，理由跟貪婪法那頁一樣是「換過來也不會變差」：出現最少的兩個放在樹的最深處，不會吃虧。 → 堆積→ 貪婪法

什麼時候會用到

  • zip、gzip、PNG 的壓縮都有這一步；JPEG 圖片和 MP3 音樂存檔前的最後一步，也常用它把數字換成長短不一的代碼。
  • 摩斯電碼是同一個想法的前輩：英文最常用的 E 是一個點，少用的 Q 要四個符號。差別是摩斯電碼靠停頓分開字母，霍夫曼編碼不用。
  • 「每次合併最小的兩堆，代價是兩堆的和，要讓總代價最小」這類題目：合併果子、接繩子，都是同一個貪婪法。
  • APCS 實作題：上面那種合併的題目，搭配堆積（優先佇列）每次拿最小的兩個。

常見誤解

誤解：常出現的給短代碼就好，代碼隨便取

正解：A 是 0、B 是 1、C 是 00 的話，收到 00 分不出是 AA 還是 C。要讓每個代碼都不是別的代碼的開頭。

誤解：同一份資料的霍夫曼樹只有一種

正解：次數一樣的時候先合誰、合起來誰放左邊都可以，每個符號的代碼會不一樣，可是編完的總長度一樣。

誤解：壓縮檔裡只要存編好的位元

正解：還要存代碼表（或每個符號出現幾次），不然解不回來。資料很短的時候，加上這張表反而比原本還大。

誤解：什麼檔案都壓得小

正解：要有些符號特別常出現才省得到。每個符號出現的次數都差不多的話，代碼幾乎一樣長；已經壓過的檔案再壓一次，也壓不下去。

實作

C

#include <stdio.h>

// 算霍夫曼編碼編完一共幾個位元：每次找出次數最少的兩個合起來，把每次合併的和加起來；counts 是每種符號出現幾次
int total_bits(const int counts[], int n) {
    int work[100];                          // 複製一份來合併，原本的陣列不動（最多 100 種符號）
    for (int i = 0; i < n; i++) {
        work[i] = counts[i];
    }
    int total = 0;
    while (n > 1) {
        for (int k = 0; k < 2; k++) {       // 做兩次：先把最小的換到最後一格，再把第二小的換到它前面
            int small = 0;
            for (int i = 1; i < n - k; i++) {
                if (work[i] < work[small]) {
                    small = i;
                }
            }
            int t = work[small];
            work[small] = work[n - 1 - k];
            work[n - 1 - k] = t;
        }
        work[n - 2] += work[n - 1];         // 最小的兩個合成一個，放在倒數第二格
        total += work[n - 2];
        n--;                                // 最後一格不要了
    }
    return total;
}

int main(void) {
    int message[] = {7, 4, 2, 1, 1};
    int even[] = {5, 5, 5, 5};
    printf("%d %d\n", total_bits(message, 5), total_bits(even, 4));
    return 0;
}

#include <iostream>

// 算霍夫曼編碼編完一共幾個位元：每次找出次數最少的兩個合起來，把每次合併的和加起來；work 是每種符號出現幾次
int total_bits(std::vector<int> work) {     // 傳值：work 是複製的一份，合併的時候不會改到原本的
    int n = work.size(), total = 0;
    while (n > 1) {

            int small = 0;
            for (int i = 1; i < n - k; i++) {
                if (work[i] < work[small]) {
                    small = i;
                }

        total += work[n - 2];
        n--;                                // 最後一格不要了

}

Python

def total_bits(counts):                 # counts 是每種符號出現幾次
    work = list(counts)                 # 複製一份來合併，原本的串列不動
    n, total = len(work), 0
    while n > 1:
        for k in range(2):              # 做兩次：先把最小的換到最後一格，再把第二小的換到它前面
            small = 0
            for i in range(1, n - k):
                if work[i] < work[small]:
                    small = i
            work[small], work[n - 1 - k] = work[n - 1 - k], work[small]
        work[n - 2] += work[n - 1]      # 最小的兩個合成一個，放在倒數第二格
        total += work[n - 2]
        n -= 1                          # 最後一格不要了
    return total

跑幾步

固定長度：每個符號一樣長15 × 3 = 45 個位元
每次用迴圈找最小的兩個找一次 O(n)，合 n − 1 次，O(n²)
用堆積O(n log n)

符號只有幾百種的時候，兩種寫法都很快；差別在符號很多的時候。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

試試看

程式運行追蹤1. 用這一頁那棵樹解碼（A = 0、B = 10、C = 110、D = 1110、E = 1111）：節點 0 到 3 是中間的節點，0 是樹根；4 到 8 是 A 到 E。下面這段程式印出什麼？

for (int k = 0; k < 6; k++) {

解析計算邏輯2. 一則訊息裡四種符號各出現 5、3、2、2 次。下面這段程式每一輪把最小的兩個換到最後兩格、合成一個，把每次合併的和加起來，就是霍夫曼編碼編完一共幾個位元。它印出什麼？

C

int counts[] = {5, 3, 2, 2};
int n = 4, total = 0;
while (n > 1) {
    for (int k = 0; k < 2; k++) {
        int small = 0;
        for (int i = 1; i < n - k; i++) {
            if (counts[i] < counts[small]) {
                small = i;
            }
        }
        int t = counts[small];
        counts[small] = counts[n - 1 - k];
        counts[n - 1 - k] = t;
    }
    counts[n - 2] += counts[n - 1];
    total += counts[n - 2];
    n -= 1;
}
printf("%d\n", total);

程式測試與除錯3. 這一頁那則訊息的五種符號出現 7、4、2、1、1 次，霍夫曼編碼編完應該是 29 個位元，下面這段程式卻印出 53。要怎麼改？

C

int counts[] = {7, 4, 2, 1, 1};
int n = 5, total = 0;
while (n > 1) {
    for (int k = 0; k < 2; k++) {
        int pick = 0;
        for (int i = 1; i < n - k; i++) {
            if (counts[i] > counts[pick]) {
                pick = i;
            }
        }
        int t = counts[pick];
        counts[pick] = counts[n - 1 - k];
        counts[n - 1 - k] = t;
    }
    counts[n - 2] += counts[n - 1];
    total += counts[n - 2];
    n -= 1;
}
printf("%d\n", total);
  1. 先把 counts 照小到大排好，再跑同一段程式
  2. 把 total += counts[n - 2] 改成 total += counts[n - 1]
  3. 把 counts[i] > counts[pick] 改成 counts[i] < counts[pick]
  4. 把 while 的條件 n > 1 改成 n > 2

總結

沒有少：常出現的符號換成了比較短的代碼，解壓縮的時候照同一張表換回來，所以一個字不差。那則 15 個字的訊息從 45 個位元變成 29 個。zip 用的招數不只這一個，這是其中之一。下次看到一份資料裡有些東西特別常出現，就可以想：常用的給短的。

課外補充

zip 用的 DEFLATE 分兩步：先找出重複出現的片段，換成「往回幾個字、抄幾個字」（LZ77）；剩下的符號再用霍夫曼編碼。開場那份報告少掉的一半，兩步都有功勞。
