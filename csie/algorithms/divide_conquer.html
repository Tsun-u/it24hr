Divide and Conquer　分治法

生活應用

一張 0.1 公釐厚的紙，每對折一次，厚度變兩倍。想知道對折 30 次有多厚，要算 30 個 2 乘在一起。手上的計算機只有加減乘除，乘法真的要按 29 次嗎？

複習

用學過的迴圈：一圈乘一次 2，30 個 2 要乘 29 次。29 次不算什麼；可是程式題常常要算一個數的十億次方（再取餘數），迴圈就要跑十億圈。 → 迴圈

換個角度看：30 個 2 可以分成兩堆，各 15 個。兩堆乘出來是同一個數，所以只要算一堆，再自己乘自己。15 個 2 又可以再分。

把大問題切成一半大的同樣問題，解完小的，再把答案合起來。

核心觀念

分治法（divide and conquer）分三步。分（divide）：把問題切成比較小的同樣問題。治（conquer）：小問題用同樣的方法解，小到可以直接知道答案就停。合（combine）：把小問題的答案組成大問題的答案。

算 a 的 n 次方：分，n 切一半；治，算出 half = a 的 n / 2 次方；合，half × half。n 是奇數時，n / 2 捨去小數，少算了一個 a，要再乘回來：2¹⁵ = 2⁷ × 2⁷ × 2。n = 0 是最小的問題，答案直接是 1。

為什麼快：n 每切一次少一半，30 → 15 → 7 → 3 → 1 → 0，切 5 次就到底；每一層最多乘 2 次。n 是十億也只切 30 次。

切出來的小問題要做幾個，每個問題不一樣。次方的兩半一模一樣，算一次就好；二分搜尋丟掉一半，也只做一個；合併排序左右兩半內容不同，兩個都要做，再花 n 步合起來，所以是 O(n log n)。 → 排序

分治通常寫成遞迴：函式裡呼叫自己去解小問題，終止條件就是「小到直接知道答案」。 → 遞迴

什麼時候會用到

  • 單淘汰賽：64 隊分成上下兩個半區，各自打出一隊，再打決賽。每個半區裡面又是一場比較小的淘汰賽。
  • 查字典、猜數字：翻開中間，答案只會在其中一半，另一半整個丟掉。二分搜尋切完只剩一個小問題要做。 → 搜尋
  • 合併排序：切成左右兩半各自排好，再把兩疊合成一疊；快速排序也是切兩邊各自排。兩個小問題都要做，力氣花在「合」。 → 排序
  • RSA 加密要算一個很大的數的幾百位數次方再取餘數，靠的就是這一頁的切一半，叫快速冪（fast exponentiation）。
  • APCS 實作題：a 的 n 次方除以 m 的餘數（n 到十億）、逆序數對、最大連續子陣列和。

常見誤解

誤解：用了遞迴，就是分治法

正解：遞迴是寫法，分治是想法。通知同學的 notify(k + 1) 每次只少一個人，要疊 n 層；分治每次切成一半大，只疊 log₂ n 層。

誤解：half × half 寫成 power(a, n / 2) * power(a, n / 2) 也一樣

正解：答案一樣，可是兩邊都真的去算了一次，每一層呼叫兩次，總共的呼叫次數跟著 n 等比例變多，白切了。算一次存進 half，再自己乘自己（試試看第二題）。

誤解：n 是奇數沒辦法切一半

正解：整數除法會捨去小數：15 / 2 是 7。2⁷ × 2⁷ 是 2¹⁴，再乘一個 2 就是 2¹⁵。忘了補這一個，連 2 的 1 次方都會算成 1 × 1 = 1，往上每一層跟著錯，幾次方都印出 1（試試看第三題）。

誤解：能切一半的問題，用分治都會變快

正解：要看「合」要花多少力氣、小問題要做幾個。找一排數字裡最大的：切兩半各找最大再比一次，每個數還是都看過一遍，跟迴圈一樣是 O(n)。

誤解：答案再大，long long 都裝得下

正解：2⁶³ 就超過 long long 的上限了。題目通常會要你算除以某個數的餘數，每乘一次就取一次餘數，數字才不會爆掉；Python 的整數沒有上限，可是數字太大一樣會變慢。

實作

C

#include <stdio.h>

// a 的 n 次方除以 m 的餘數；m 不超過 1000000007 的話，兩個餘數相乘放得進 long long
long long power_mod(long long a, long long n, long long m) {
    if (n == 0) {                               // 最小的問題：0 次方是 1
        return 1;
    }
    long long half = power_mod(a, n / 2, m);    // 治：只算一半，存起來
    long long result = half * half % m;         // 合：自己乘自己，乘完就取餘數
    if (n % 2 == 1) {                           // n 是奇數：補回少算的那個 a
        result = result * (a % m) % m;
    }
    return result;
}

int main(void) {
    printf("%lld %lld\n", power_mod(2, 30, 1000000007), power_mod(3, 1000000000, 1000000007));
    return 0;
}

Python

def power_mod(a, n, m):                  # a 的 n 次方除以 m 的餘數
    if n == 0:                           # 最小的問題：0 次方是 1
        return 1
    half = power_mod(a, n // 2, m)       # 治：只算一半，存起來
    result = half * half % m             # 合：自己乘自己，乘完就取餘數
    if n % 2 == 1:                       # n 是奇數：補回少算的那個 a
        result = result * (a % m) % m
    return result

跑幾步

迴圈一個一個乘n 次，O(n)
切一半、算一次存起來：層數 log₂ n，每層最多乘 2 次O(log n)
切一半、兩邊各算一次：呼叫次數跟著 n 等比例變多O(n)

2 的 30 次方乘 9 次；十億次方大約乘 40 幾次。Big-O 的意思和怎麼算，在資料結構的附錄。 → 時間複雜度

試試看

程式運行追蹤1. 下面這段程式印出什麼？

C

int f(int n) {
    if (n == 0) {
        return 0;
    }
    return f(n / 2) + 1;
}

printf("%d\n", f(13));
  1. 13
  2. 5
  3. 4
  4. 3

程式效能分析2. 把 half × half 寫成兩邊各呼叫一次，函式一共會被呼叫幾次？calls(n) 照那個寫法數：自己這一次，加上兩邊各自的次數。下面這段程式印出什麼？

C

int calls(int n) {
    if (n == 0) {
        return 1;
    }
    return 1 + calls(n / 2) + calls(n / 2);
}

printf("%d\n", calls(16));
  1. 6
  2. 17
  3. 32
  4. 63

程式測試與除錯3. 想算 2 的 5 次方（32），結果印出 1。要怎麼改？

C

int power(int a, int n) {
    if (n == 0) {
        return 1;
    }
    int half = power(a, n / 2);
    return half * half;
}

printf("%d\n", power(2, 5));
  1. 把終止條件改成 n == 1 時回傳 1
  2. 把 return half * half 改成 return half * half * a
  3. n 是奇數時，改成回傳 half * half * a
  4. 把終止條件回傳的 1 改成 a

總結

不用乘 29 次：2 的 30 次方是兩個「2 的 15 次方」相乘，15 次方再切，一路切到 0 次方，總共只乘 9 次，答案是 1073741824。0.1 公釐的紙對折 30 次，厚度超過 100 公里。下次碰到一個大問題，可以先想：能不能切成一半大的同樣問題，解完再合起來？每切一次就少一半，再大的問題也切不了幾次。

課外補充

逆序數對：一排數字裡，有幾對是大的排在小的前面。兩層迴圈要 O(n²)；照合併排序切兩半，左半、右半各自數完，合併的時候每從右半拿一個數，左半還沒拿的那些都比它大，一次加上去，O(n log n)。 → 排序
